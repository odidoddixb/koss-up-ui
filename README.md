# 1번 메인 화면·팀 코드 통합 (담당: 김채린 )

조달청 재난 대응 게임 **프로젝트 골든타임**의 메인 화면과 담당 모듈을 연결한 통합본입니다.
현재 **1번 메인 UI + 2번 나라장터 계약 심사 + 5번 재난·뉴스 + 6번 게임 시스템**을 연결했습니다.
**3번 원자재 비축·4번 혁신제품 지원은 아직 코드 미전달로 준비 중**입니다.

메인은 화면과 진행 순서를 연결하고, 날짜·예산·점수·저장은 **6번 공통 세션**에서 관리합니다.
실행 안내·팀 연동 방법·내부 코드 로직을 이 README 하나에 정리했습니다.
Mac에서 MD 파일이 열리지 않으면 `team-readme.html`에서 바로 읽고 복사하거나 `README.txt`를 이용해 주세요.

## 실행 방법

전체 코드 ZIP을 풀고 **`index.html`이 있는 폴더**에서 실행합니다.

```bash
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`으로 접속합니다. 이미지·음원·modules 폴더의 상대 경로를 유지해 주세요.
별도 설치나 빌드 과정은 없습니다.

- 단일 HTML 배포본: `goldentime-standalone.html` 하나에 코드·이미지·음원이 포함됩니다. 전체 코드 ZIP과 별도로 제공합니다.
- 5번 원본 비교 데모: 로컬 서버에서 `/original-news/index.html`로 접속합니다. 임시 세션을 사용하는 독립 데모입니다.
- 온라인 통합본: https://goldentime-office.growncabin17.chatgpt.site
- 온라인 사이트는 현재 소유자 전용이라 팀원 접근이 제한될 수 있습니다. 팀 공유 시 코드 ZIP을 노션에 직접 첨부해 주세요.

## 화면 구성

- **시작 화면**: 이름 입력. 여성 주무관으로 고정하며 성별 선택은 없습니다.
- **메인 업무 화면**: 날짜·예산·청렴도, 뉴스 미리보기, 업무 카드, 오늘의 업무 체크리스트, 재난 대응 현황을 표시합니다.
- **나라장터 계약 심사**: 업체 조사 후 승인·반려·추가 조사(보류)를 선택합니다.
- **업무 종료**: 아침 뉴스 미리보기 바로 아래의 `오늘 업무 마치기` 버튼으로 하루를 마감합니다.
- **뉴스·출근 화면**: 5번 뉴스와 다음 날 출근 대기를 같은 무대에서 표시합니다.
- **최종 결과**: 5일차 저녁 뉴스 후 성과·랭킹·새 게임을 표시합니다.

## 확정한 진행 방식

```text
이름 입력 → 1일차 아침 뉴스 → 업무 시작
→ 오늘 업무 마치기 → 퇴근 확인 → 저녁 뉴스
→ 다음 날 출근 대기 → 출근하기 클릭 → 아침 뉴스 → 업무 시작
→ 5일차 저녁·엔딩 뉴스 → 최종 결과
```

- 총 **5일**, 시작 예산 **3,000억 원**입니다.
- **1일차 밤 23:47, 해원시 규모 7.8 지진**은 5번 시나리오를 사용합니다.
- 계약 심사 마감은 계약 업무만 종료합니다. 날짜는 메인의 하루 마감에서 한 번만 넘깁니다.
- 저녁 뉴스가 끝나도 아침 뉴스가 자동으로 시작되지 않습니다. 출근 버튼을 직접 눌러야 합니다.
- 아침 뉴스의 `업무 시작` 확인 시 전날 밤 결과를 공통 세션에 반영합니다.
- 5일차 밤 결과는 다음 날로 넘기지 않고 엔딩 뉴스의 최종 진척도를 사용합니다.
- 새 게임은 진행·계약·뉴스·이름을 초기화하고 이름 입력으로 돌아갑니다. 완료 랭킹은 유지합니다.

## 담당별 연결 상태

| 담당 | 현재 상태 | 연결 내용 |
| --- | --- | --- |
| 1번 메인 | 연결 | 화면, 이름 입력, 업무 진입, 하루 마감·출근, 결과 화면 |
| 2번 계약 심사 | 연결 | 판정·예산 결과, 조사 횟수, 계약 상태 저장, 뉴스에 당일 판정 건수 전달 |
| 3번 비축 관리 | 준비 중 | 실제 업무·점수·뉴스 결과 연결 필요 |
| 4번 혁신제품 | 준비 중 | 실제 업무·점수·뉴스 결과 연결 필요 |
| 5번 재난·뉴스 | 연결 | 실제 6번 세션, 아침·저녁·지진·엔딩, 원본 이미지, 지난 뉴스 |
| 6번 시스템 | 연결 | 공통 상태·저장·정산·랭킹, 2번 기준의 청렴도 판정 확장 |

3·4번은 아직 실제 평가하지 않습니다. 해당 분야의 뉴스는 5번의 대체값을 사용하므로 **실제 3·4번 플레이 결과가 아닙니다.**

## 2번 기준의 계약 판정

| 판정 | 의미 | 청렴도 계산 가중치 |
| --- | --- | --- |
| `correct` | 올바른 승인·반려 | +100 |
| `ordinaryWrong` | 일반 오답 | −40 |
| `falseApproval` | 부실 업체 승인 | −100 |
| `unresolved` | 마감 시 미확정 | −60 |

```text
청렴도 = max(0, round((정답×100 − 일반 오답×40 − 부실 승인×100 − 미처리×60) / 전체 판정 건수))
```

가중치는 매번 현재 점수에 단순히 더하는 방식이 아니라 **누적 판정 건수로 계산**합니다.
보류는 최종 판정이 아니며, 마감까지 승인·반려하지 않으면 미처리가 됩니다.
하루 계약 2~5건, 조사 5회를 사용하고, 같은 조사·계약 결과가 중복 반영되지 않도록 처리합니다.

## 연결 방법

메인에서 공통 세션과 뉴스 인스턴스를 이미 생성하므로, 각 담당 모듈에서는 **새 세션을 만들지 말고** 아래 API를 사용합니다.

```js
// 현재 공통 상태 읽기: getState()는 복사본입니다.
const game = GoldenTime.getState();
const day = game.day;

// 5번이 제공하는 오늘의 원자재 시황
const market = GoldenTime.news.getMarket(day);

// 메인으로 돌아가기
GoldenTime.navigate("home");
```

### 공통 점수·예산 반영

상태 변경은 `GoldenTime.applyOutcome(outcome)`으로 전달합니다. 이 함수는 공통 세션에 결과를 적용하고 메인 화면을 갱신합니다.
`outcome`의 세부 형식·단위·판정 기준은 `docs/reference/GAME_SYSTEM_INTEGRATION-original.md`와 `SCORING_CRITERIA-original.md`를 확인해 주세요.

```js
// 4번 형식 예시입니다. 예산·결과는 실제 업무 결과로 전달합니다.
GoldenTime.applyOutcome({
  source: "innovation",
  label: "혁신제품 시범구매 결과",
  budgetDelta: -5,
  innovationDecision: "success" // success | partial | failure
});
```

### 뉴스에 하루 결과 전달

공통 시스템의 `applyOutcome`과 **별개로**, 당일 결과가 확정되면 아래 형태로 한 번 전달합니다.
아래 숫자는 연결 형식 예시이며 실제 업무 결과로 바꿔야 합니다.

```js
const day = GoldenTime.session.getState().day;

// 2번: 현재 통합본에서 자동 전달합니다. 별도로 중복 호출하지 않습니다.
// GoldenTime.reportDay(day, {
//   contract: { correct: 2, ordinaryWrong: 0, falseApproval: 1, unresolved: 0 }
// });

// 3번: 당일 최종 필요량·확보량
GoldenTime.reportDay(day, {
  reserve: { requiredQuantity: 100, availableQuantity: 80 }
});

// 4번: 당일 최종 결과
GoldenTime.reportDay(day, {
  innovation: { decision: "success" } // success | partial | failure
});
```

- 날짜 증가·`closeDay()`·아침 결과 반영은 메인 연동에 맡기고 담당 모듈에서 중복 실행하지 말아 주세요.
- `GoldenTimeBridge`는 2번 계약 프레임 전용입니다. 3·4번은 공통 `GoldenTime` API를 사용합니다.
- UI용 `state`나 `getState()` 반환 객체를 직접 수정해도 공통 세션은 갱신되지 않습니다.

## 이미지·소리

5번 원본 ZIP의 이미지 16장을 `assets/news/`에 그대로 보관하며, `integration.js`의 `newsAssets`에서 설정합니다.

- 달이: `happy`, `calm`, `worry`, `sad` 4종
- 시민: 대피 주민·운전기사·간호사, 각 `happy`, `worry`, `upset` 3종
- 배경: 재난·창고·사무실 3장. 지진·교량 기사는 같은 재난 사진을 사용합니다.
- 시민의 `joy`·`relief`는 happy, `angry`·`upset`은 upset에 연결합니다.

원본 효과음의 음정·음량·호출 시점은 유지하며, Safari에는 실제 WAV 파일을 재생하는 별도 경로를 추가했습니다.
뉴스 상단의 `소리 다시 연결`에서는 확인음 재생 컨트롤과 재생 오류를 표시합니다.
**현재 Safari 음향 문제는 사용자 기기에서 재확인이 필요한 상태이며, 해결 완료로 기록하지 않습니다.**

## 저장·주의 사항

- 진행과 랭킹은 브라우저의 `localStorage`에 저장합니다. 서버·팀원 간 공유 저장은 없습니다.
- 브라우저·접속 주소·포트가 다르면 저장 공간도 달라집니다. 브라우저 데이터를 삭제하면 기록이 사라질 수 있습니다.
- 새로고침 후 이어하기 또는 출근 대기로 복원합니다.
- `integration.js`가 날짜·화면 전환을 연결합니다. 다른 모듈에서 별도 날짜 증가나 자동 아침 뉴스 호출을 추가하지 말아 주세요.
- 원본과 달라진 부분은 `docs/INTEGRATION_CHANGES.md`, 제공받은 원본은 `docs/reference/`에 있습니다.

## 코드 로직

### 상태 관리

공통 세션은 날짜·예산·점수·업무 이력·재난 지표·아침 반영 대기 결과를 관리합니다.
`app.js`의 state는 화면 표시용이며 `integration.js`의 render가 공통 값을 반영합니다.
계약의 조사·선택 상태와 5번 뉴스 상태는 별도로 저장하되, 점수·예산의 기준은 공통 세션 하나입니다.
`app.js`에 초기 UI 구현이 남아 있지만 현재 계약·뉴스·정산의 최종 연결은 `integration.js`를 기준으로 확인해 주세요.

### 주요 함수

| 함수 | 역할 |
| --- | --- |
| `counts(day)` | 공통 이력에서 계약 판정 건수 집계 |
| `getContract(day)` | 날짜별 계약 생성·조회, 공통 이력으로 판정 복원 |
| `saveContract(snapshot)` | 현재 날짜의 미마감 계약 상태 저장 |
| `applyContract(outcome)` | 계약 ID·마감 여부 검증 후 한 번만 결과 반영 |
| `settleContract()` | 미확정 계약을 미처리로 반영하고 계약 업무 마감 |
| `render()` | 공통 상태·계약 상태를 메인 UI에 반영 |
| `endDay()` | 퇴근 확인, 계약 마감, 공통 하루 정산, 저녁 뉴스 연결 |
| `showNight(day)` | 밤 뉴스 완료 후 출근 대기 또는 최종 결과로 이동 |
| `showCommute(background)` | 다음 날 출근 대기 화면 준비·표시 |
| `showMorning(fromCommute)` | 아침 뉴스 완료 후 업무 화면으로 이동 |
| `restartGame()` | 이전 세션 연결을 해제하고 새 게임 생성 |

### 계약 결과 처리

```text
계약 화면에서 판정 확정
→ GoldenTimeBridge.applyContract(outcome)
→ 날짜·마감 여부·계약 ID 검증
→ 같은 날짜 + 계약 ID의 기존 결과 확인
→ session.applyOutcome()
→ 5번 reportDay()에 판정 건수 전달
→ 메인 화면 갱신
```

이미 기록된 계약 결과는 다시 예산을 차감하지 않습니다.
**3·4번용 일반 applyOutcome에는 계약과 같은 중복 식별자 검증이 아직 없으므로, 추가 연결 시 완료·제출 상태 관리가 필요합니다.**

### 하루 마감·뉴스 전환

```text
퇴근 확인 → 미확정 계약 마감 → 마감한 날짜 저장
→ session.closeDay() 한 번 → 마감한 날짜의 밤 뉴스
→ 다음 날 출근 대기 → 직접 출근 클릭 → 아침 뉴스
→ 업무 시작 확인 시 전날 밤 결과 반영 → 업무 화면
```

`busy`는 뉴스 진행 중 중복 마감을 막고, inert 속성은 뒤의 업무 화면 조작을 제한합니다.
flow 저장값의 night·morning·ending 단계로 중단된 진행을 복원합니다.
출근 버튼은 새로운 포인터 입력 또는 반복이 아닌 키 입력으로 눌러야 동작합니다.
아침 뉴스 중에는 출근 배경을 숨겨 업무 화면으로 바로 이어지게 합니다.
5일차 최종 복구율은 `getNightNews(5).progress`를 사용합니다.

### 새 게임 처리

이전 세션의 페이지 생명주기 저장 연결을 해제하고 pause한 뒤 진행·계약·flow·뉴스·프로필을 초기화합니다.
새 세션·뉴스 인스턴스를 생성하고 공개 API의 참조를 교체한 후 이름 입력 화면을 표시합니다.
단순 새로고침으로 초기화하지 않으므로 이전 세션의 pagehide 저장이 완료 게임을 다시 덮어쓰는 문제를 피합니다.
랭킹과 사용자의 음소거 선택은 유지합니다. 다른 모듈은 예전 세션을 장기간 보관하지 말고 작업 시점의 `GoldenTime.session`을 사용해 주세요.

### 추가 모듈 연결 시

3·4번 결과 API만 호출해도 준비 중 UI가 자동 해제되는 구조는 아닙니다.
실제 업무 화면, 완료 상태, 준비 중 배지·체크리스트와 평가 범위도 함께 연결해야 합니다.
원본 대비 세부 변경 기록은 `docs/INTEGRATION_CHANGES.md`에 남겨 둡니다.

## 검증 방법

Node.js가 있으면 아래 로직 검사를 실행할 수 있습니다.

```bash
node tests/scoring-and-flow.cjs
node tests/news-original-preservation.cjs
```

DOM 기반 통합 검사로 계약 판정·중복 반영 방지·미처리 감점·5일 진행·출근 대기·최종 결과·새 게임을 확인했습니다.
이미지 경로와 단일 HTML의 리소스 포함, 모사 환경의 Safari 음원 재생 호출도 확인했습니다.

## 아직 확인하지 못한 것

- 3·4번 실제 코드를 연결한 전체 플레이와 최종 점수 균형
- 최신 Safari용 음원 재생 방식의 실제 사용자 기기 스피커 출력
- 여러 화면 크기·브라우저에서의 최종 시각 검증
- 다른 담당 모듈을 추가했을 때의 저장 데이터·중복 결과 처리
