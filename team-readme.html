# 프로젝트 골든타임 — 메인 화면 및 1·2·3·4·5·6번 통합

조달청 재난 대응 게임의 메인 화면과 계약·비축·혁신제품·뉴스·공통 시스템을 연결한 통합본입니다.
날짜·예산·점수·저장은 **6번 공통 세션 하나**를 기준으로 하고, 각 담당 모듈의 시나리오·판정 로직을 사용합니다.
실행 안내·연동 방법·내부 로직을 이 README에 모았습니다.

MD 파일이 열리지 않으면 `team-readme.html`에서 읽고 복사하거나 `README.txt`를 이용할 수 있습니다.

## 실행 방법

전체 코드 ZIP을 풀고 `index.html`이 있는 폴더에서 실행합니다.

```bash
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 엽니다. 서버를 실행한 터미널은 켜 두고, 종료할 때 Control+C를 누릅니다.
별도 설치·빌드 없이 실행합니다. `assets`, `modules` 폴더 구조를 유지해 주세요.

- 단일 HTML: 별도 제공하는 `goldentime-standalone.html`에 코드·스타일·이미지·음원을 포함합니다.
- 온라인 통합본: https://goldentime-office.growncabin17.chatgpt.site
- 온라인 사이트는 소유자 전용입니다. 팀원에게는 전체 코드 ZIP을 직접 공유할 수 있습니다.

## 진행 흐름

```text
이름 입력 → 1일차 아침 뉴스 → 업무 시작
→ 계약 심사 / 비축 관리 / 혁신제품 지원
→ 오늘 업무 마치기 → 퇴근 확인 → 저녁 뉴스
→ 다음 날 출근 대기 → 직접 출근 클릭 → 아침 뉴스 → 업무 시작
→ 5일차 엔딩 뉴스 → 최종 결과·랭킹
```

- 총 5일, 시작 예산 3,000억 원입니다. 캐릭터는 여성 주무관이며 이름만 입력합니다.
- 1일차 밤 23:47, 해원시 규모 7.8 지진은 5번 시나리오를 사용합니다.
- 업무 종료 버튼은 뉴스 미리보기 바로 아래에 있습니다.
- 계약 심사 마감은 계약 업무만 끝냅니다. 날짜는 메인의 하루 마감에서 한 번만 증가합니다.
- 출근 대기 하단 수치는 직전 저녁 뉴스 결과입니다. 실제 공통 세션 반영은 다음 날 아침 뉴스 확인 때 이뤄집니다.
- 세 업무가 끝나면 체크리스트가 3/3으로 표시됩니다. 미완료 업무가 있으면 마감 확인 창에 안내합니다.
- 새 게임은 이름·계약·재고·혁신제품 지원·뉴스·진행을 초기화하고, 완료 랭킹과 음소거 선택은 유지합니다.
- 이전 통합본의 진행도 읽을 수 있으나, 이미 지나간 날짜의 3·4번 선택 결과를 임의로 생성하지 않습니다. 세 업무를 처음부터 플레이하려면 새 게임으로 시작합니다.

## 담당별 연결

| 담당 | 연결 내용 |
| --- | --- |
| 1번 | 메인 UI, 업무 탭, 체크리스트, 하루 마감·출근, 결과 화면 |
| 2번 | 업체 조사·계약 판정·예산 결과, 미처리 마감, 뉴스 판정 건수 전달 |
| 3번 | 공통 예산·5번 시황으로 자재 업무 확정, 경제 평가 자료·뉴스 결과 전달 |
| 4번 | 지원금 집행, 날짜별 활용 평가, 혁신 평가 자료·잠정/최종 뉴스 전달 |
| 5번 | 실제 공통 세션으로 뉴스·지진·재난 목표·아침 결과 큐·엔딩 처리 |
| 6번 | 날짜·예산·네 평가 항목·자동 저장·랭킹 관리 |

## 2번 계약 판정

```text
청렴도 = max(0, round((정답×100 − 일반 오답×40 − 부실 승인×100 − 미처리×60) / 전체 판정 건수))
```

가중치를 현재 점수에 단순 가산하지 않고 누적 판정 건수로 계산합니다.
보류는 확정 판정이 아니며, 마감까지 미확정이면 `unresolved`로 처리합니다.
계약 결과는 같은 날짜·계약 ID 기준으로 중복 반영을 막습니다.

## 3번 비축 관리

철강·시멘트·경유·목재를 매입·조합·방출·매각합니다. 처리 순서는 매입 → 조합 → 방출·매각입니다.
원본 `material-core.js`가 재고·위험 비용·당시 실행 가능한 최선의 선택을 계산합니다.

- 1일차 선제 비축, 2일차 긴급 방출, 3일차 경유, 4일차 대체 조합, 5일차 재고 정리를 진행합니다.
- `news.getMarket(day)`의 실제 시황을 사용합니다.
- 확정 시 `economicDecision`, `budgetAssessment`, `budgetDelta`를 6번에 보냅니다.
- 필요량·확보량은 별도로 뉴스에 전달합니다.
- 예산 잔액은 `budgetDelta`로 한 번만 변경합니다. 예산 평가 자료로 다시 차감하지 않습니다.
- 입력 초안·재고·확정 상태를 저장하고, 탭을 옮겨도 입력을 유지합니다.
- 메인 비축률은 마지막 확정된 비축 업무의 목표 확보율입니다.

## 4번 혁신제품 지원

기업 대표와 대화하고 성능·검증·납품 조건을 확인한 뒤 전액 지원·일부 지원·거절을 선택합니다.

- 지원 즉시 지원금만 예산에서 차감합니다.
- 활용 평가 확인일에 `innovationDecision`과 `budgetAssessment`를 한 번 전달합니다.
- **1일차 드론은 3일차 아침 뉴스 확인 후 평가합니다.** 1일차 뉴스의 결과는 잠정 판단입니다.
- 2~5일차 기업도 원본 시나리오의 확인일에 평가합니다.
- 뉴스에는 해당 날짜의 기업 판단을 전달합니다. 이전 드론 결과로 현재 날짜의 기업 뉴스를 덮어쓰지 않습니다.
- 기존 공통 이력과 모듈 저장을 대조해 지원금·활용 평가 중복 반영을 방지합니다.

## 공개 API

메인에서 이미 만든 세션·뉴스를 사용합니다. 담당 모듈에서 별도 세션이나 뉴스 인스턴스를 만들지 않습니다.

```js
const game = GoldenTime.getState(); // 복사본 + 표시용 profile
const day = game.day;
const market = GoldenTime.news.getMarket(day);

GoldenTime.openTab(0); // 계약 심사
GoldenTime.openTab(1); // 비축 관리
GoldenTime.openTab(2); // 혁신제품 지원
GoldenTime.navigate("home");
```

결과 전달 형식은 아래와 같습니다. 현재 연결된 모듈에서 자동 호출하므로 예시를 추가로 실행하면 안 됩니다.

```js
// 공통 시스템용 예시: 실제 선택의 비용·결과를 전달합니다.
GoldenTime.applyOutcome({
  source: "sme-support",
  label: "혁신제품 활용 결과",
  innovationDecision: "success",
  details: { innovationId: "drone" }
});

// 뉴스용 결과는 공통 점수/예산 반영과 별개입니다.
GoldenTime.reportDay(day, {
  reserve: { requiredQuantity: 100, availableQuantity: 80 }
});
GoldenTime.reportDay(day, {
  innovation: { decision: "success" }
});
```

6번의 세부 결과 구조·단위는 `docs/reference/GAME_SYSTEM_INTEGRATION-original.md`와 `SCORING_CRITERIA-original.md`를 확인해 주세요.
`GoldenTimeBridge`는 2번 프레임 전용입니다. 3·4번은 공통 세션과 메인 래퍼로 연결합니다.
날짜 증가·아침 결과 반영·밤 뉴스 호출을 각 담당 모듈에서 중복 실행하지 않습니다.

## 내부 로직

| 함수 | 역할 |
| --- | --- |
| `initializeWorkModules()` | 같은 세션·뉴스를 사용해 3·4번 인스턴스 생성 |
| `applySharedOutcome()` | 공통 결과 반영·화면 갱신, 자재 이벤트 및 혁신 지원/평가 중복 방지 |
| `recoverInnovation()` | 공통 이력으로 혁신 지원·활용 평가 저장 복원 |
| `getContract()` / `applyContract()` | 날짜별 계약 복원·검증·판정 반영 |
| `settleContract()` | 미확정 계약을 미처리로 마감 |
| `resolveMorningWork()` | 아침 확인 후 당일 활용 평가와 모듈 화면 갱신 |
| `endDay()` | 미완료 안내 → 계약 마감 → 당일 평가·뉴스 보고 → 하루 정산 |
| `showNight()` / `showCommute()` / `showMorning()` | 저녁 뉴스·명시적 출근·아침 뉴스 연결 |
| `restartGame()` | 이전 저장 연결 해제 → 모듈 저장 삭제 → 새 세션·모듈 생성 |

- 화면용 state와 실제 공통 상태를 구분합니다. UI state를 직접 수정해도 공통 점수는 바뀌지 않습니다.
- `busy`와 inert로 뉴스 중 마감·뒤 화면 조작을 제한합니다.
- 3·4번 화면은 탭 전환 시 제거·재생성하는 대신 같은 mount를 다시 붙여 인스턴스를 유지합니다.
- 4번의 원본 코드는 전용 session 래퍼로 연결해 메인도 함께 갱신합니다.
- `source + eventId`로 자재 결과를, `source + innovationId + 지원/평가 구분`으로 혁신 결과를 중복 검사합니다.
- 3·4번 세부 시나리오·판정·UI 코드와 5번 최신 JS/CSS는 전달받은 원본을 유지합니다. 메인 CSS의 전역 header/footer 배치만 임베드 영역에서 보정합니다.
- 새 게임에서는 이전 세션의 생명주기 저장을 해제합니다. 예전 세션을 다시 저장하거나 참조하지 않도록 모듈도 재생성합니다.

## 이미지·소리

뉴스 원본 이미지 16장(달이 4종·시민 9종·배경 3장)은 `assets/news/`에 보관합니다. 현재 메인 화면의 뉴스 달이는 사용자 참고 이미지의 주황색 캐릭터 디자인을 기준으로 만든 투명 배경 이미지 4종을 사용합니다. 기본은 `dari-reference.webp`, 기쁨·걱정·슬픔은 `dari-reference-happy.webp`, `dari-reference-worry.webp`, `dari-reference-sad.webp`입니다. `modules/golden-time-news-expressions.js`가 현재 보이는 기사·쪽·업무 결과·시민 만족도에 맞춰 표정을 갱신합니다. 아침 2~3일차는 걱정, 4일차는 슬픔을 기본으로 하고 업무 안내 쪽은 차분한 표정을 표시합니다. 저녁에는 업무 결과와 지도 쪽 시민 반응을 반영합니다. 결과 카드에 포인터를 올리면 해당 업무의 반응을 보여 줍니다. 5번 뉴스 원본, 대사·점수·소리·날짜 진행 로직은 변경하지 않았습니다.
5번 최신 ZIP의 JS/CSS는 현재 뉴스 코드와 바이트 단위로 일치하므로 다시 수정하지 않았습니다.
기존 Safari용 `golden-time-audio.js`와 WAV도 유지합니다.
실제 스피커 출력은 모사 테스트로 확인할 수 없으므로 최신 기기 재확인은 별도로 필요합니다.

조달청 로고는 제공받은 가로·세로 PDF의 벡터 경로를 사용합니다. 사이드바에는 대비를 위해 흰 글자 버전을 적용했습니다. 나라장터 주무관은 참고 시트를 바탕으로 이미지 편집 도구에서 정리한 투명 PNG이며, 픽셀 그대로의 원본 크롭은 아닙니다. 원본 PDF는 `docs/reference/branding/`에 보관했습니다.

## 저장

공통 세션·계약·뉴스·프로필·랭킹과 함께 아래 두 키를 사용합니다.

| 키 | 내용 |
| --- | --- |
| `goldentime-material-v1` | 3번 재고·입력 초안·확정 상태 |
| `golden-time-innovation-progress-v4` | 4번 지원 결정·활용 평가·뉴스 보고·질문 기록 |

같은 브라우저·출처의 localStorage에 저장하며 서버나 팀원 간 공유 저장은 없습니다.
새 게임에서는 공통 진행과 두 모듈 기록을 함께 지우되 완료 랭킹은 유지합니다.
3·4번 독립 데모의 저장 키와 본게임 저장 키는 분리되어 있습니다.

## 검사

Node.js가 있으면 아래 검사를 실행할 수 있습니다.

```bash
node tests/scoring-and-flow.cjs
node tests/material-logic.test.cjs
node tests/material-ui.test.cjs
node tests/news-original-preservation.cjs
```

통합 DOM 검사로 다음을 확인했습니다.

- 실제 3번 입력 계획으로 5일간 매입·조합·방출·매각 및 재고 이월
- 4번 지원금 차감, 1일차 잠정 뉴스, 3일차 지연 평가
- 세 업무 체크리스트·공통 예산·당일 뉴스 보고 갱신
- 탭 이동 시 초안 유지, 새로고침·모듈 저장 누락 시 공통 이력 복원

## 뉴스·심사 화면 표시 보완

- 기사 카드의 크기는 기존 뉴스 화면과 동일하게 유지합니다. `assets/news/office-hd.webp`는 기존 사무실 사진을 참고해 AI로 재구성한 선명한 삽화이며 원본 사진은 보관했습니다.
- 뉴스 시민 반응을 크게 표시하고, 계약 판정 시 주무관의 큰 표정과 판정 문구를 함께 표시합니다. 계약 표정은 기존 주무관 디자인을 참고해 표정별로 개별 생성한 고해상도 투명 이미지(`reaction-*.webp`)를 사용합니다. 배경과 다른 캐릭터가 포함된 작은 시트 조각은 표시하지 않습니다.
- 뉴스의 달이 상하 움직임과 마우스 시차 효과를 제거했습니다.
- 비축 화면의 임무·계산기 영역도 파랑·보라 팔레트로 통일하고 계약·비축 탭의 대시보드 이동 버튼을 하나로 정리했습니다.
- 효과음, 계약·비축·혁신 평가와 날짜 진행 로직은 변경하지 않았습니다.

- `assets/news/disaster-hd.webp`는 기존 재난 현장 그림을 참고해 AI로 재구성한 선명한 삽화입니다. 원본 `disaster.jpg`도 보관합니다. 이미지의 WebP 인코딩은 화질 96으로 설정하고, 크기 변경 없이 저장했습니다.
